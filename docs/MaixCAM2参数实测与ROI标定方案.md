# MaixCAM2 参数实测与 ROI 标定方案

本方案对应当前 [code/main.py](../code/main.py)，以 `320×240`、黑胶带横线巡线、上方竖线地标计数为对象。依据现有项目方案与源码，不适用于 `main_dual_roi.py`。前景提取已改为 LAB 阈值筛选，尚未连接设备验证；文中的现有数值是**待验证初值**，采样量与测试次数是建议，不是题目规定或实测结果。

交付目标：得到一组可复现的参数，以及证明它在规定光照、姿态、速度下有效的截图、记录和计数结果。顺序为：**固定成像 → LAB 阈值标定 → 主/横线 ROI → 横线筛选 → 误差标定 → 动态裁剪/竖线 → 时序计数 → 离线验收**。前一阶段不过关，不用后一阶段的门限掩盖问题。

## 2. 上板前准备与记录

1. 准备 MaixCAM2、正式使用的镜头/胶带/地面、稳定供电、电脑与 MaixVision、尺子、可重复摆放的车体位置标记。先静止和手推调试，再启用运动控制。
2. 固定安装高度、俯仰角、左右偏转、画面方向与焦点；拍摄安装状态。改变其中任一项后，至少复核 ROI、`Target_Y`、触发中心和色块尺寸。
3. 记录 MaixVision、固件、MaixPy 版本、相机型号、代码版本或文件校验值；项目文档记载 OS04D10，仍以实际设备为准。
4. 当前代码没有明确设置曝光、白平衡或帧率。先观察亮度是否稳定，再决定保留自动模式还是采用固定设置；固定设置只在当前固件支持并验证后使用。光照变化范围大时，必须复测自动模式的适应过程，不能假定“锁曝光一定更好”。相机设置方法以 [官方相机说明](https://wiki.sipeed.com/maixpy/doc/zh/vision/camera.html) 为准。
5. 使用单独的标定副本，避免同时运行两个占用摄像头的程序。不要混入参照入口。当前程序启动还会初始化 UART，串口映射失败需先按日志处理，不能误判为视觉参数问题。
6. 标定期间继续使用 `320×240`。MaixVision 预览若缩放，不能直接把屏幕坐标当图像坐标；需扣除边框/留白后，按原图宽高换算，或直接从变量读取。
7. 每次只改变一个参数，或必须联动的一组参数；用相同场景对照修改前后结果，失败就回退到上一组。

建立场景集：理想巡线位置、允许范围两端的平移、左右偏转、远/近竖线、无地标纯横线、阴影、反光、两个相邻地标、短暂遮挡。精度/速度/持续运行时长应来自题面和控制要求；当前材料没有完整评分与误差上限，留在记录表中待填。

### 2.1 一次标定的执行清单

| 阶段 | 操作与观察画面 | 进入下一步的条件 | 保存证据 |
| --- | --- | --- | --- |
| A 成像 | 固定相机，观察原图中的近/远细线、阴影、反光 | 目标可分辨，无明显失焦和严重拖影 | 安装照片、原图、曝光/白平衡设置 |
| B LAB | 采样横线、竖线、背景，调六项范围，看 `binary_img` | 两类目标连续，背景不与目标明显粘连 | 六项阈值、三类光照的原图与掩膜 |
| C ROI | 手推到允许偏移/朝向边界，看原图叠加 | 合法目标始终落在对应检测带内 | 极限姿态截图、整数 ROI 坐标 |
| D 横线 | 先筛错线，再标 `Target_Y` 和方向误差 | 拟合到正确横线，重复摆车零点稳定 | 有效率、pos/head 分布、错线截图 |
| E 特征 | 看 `V_binary_img`，量裁剪后尺寸和间距 | 横线残留已清除，最短地标仍通过 | w/h/像素数/d 与拒绝原因 |
| F 时序 | 慢推后逐级提速，检查确认与清空 | 一次通过只计一次，相邻地标能重新计数 | 真值数、逐帧状态、触发位置与速度 |

建议为每轮建立 `日期_场景_轮次` 文件夹；截图名加 `原图/掩膜/裁剪` 和帧号，保存同一参数版本。顺序运行显示模式时，各截图并非同一帧，动态场景不能逐像素对照。调参场景与验收场景分开：参数确定后，用未参与调参的新位置和新通过过程复测。

## 3. 先看清程序在哪一步丢掉目标

现有程序已经生成三个适合观察的图像。标定副本每次选择一种显示：

| 显示对象 | 在循环末尾使用 | 检查内容 |
| --- | --- | --- |
| 原图叠加结果 | `disp.show(img)` | 目标是否在 ROI 内，横线拟合位置、色块框、误差、计数 |
| 预处理后二值图 | `disp.show(binary_img)` | 黑胶带是否连续变白、背景是否变黑；主 ROI 外已被清零 |
| 竖线裁剪二值图 | `disp.show(V_binary_img)` | 横线是否被清干净，竖线是否仍保留足够高度 |

默认屏幕显示 `binary_img`，因此看不到绘制在 `img` 上的框和状态文字。需要看框时只在标定副本中切换到 `disp.show(img)`，不要因默认画面没有彩框而判断绘制失败。一次只保留一个 `disp.show(...)` 调用。

这三种调用使用现有变量，不需要新增设备 API。但当前程序**没有**参数滑块、自动采样、CSV 保存或拒绝原因显示；后面的候选统计需要在标定副本增加临时日志，或人工记录。正式控制串口继续保留四字段，不把调试文本混入其中。

记录位置要在筛选之前：横线在 `for a in lines` 内记录端点、`abs(dx)`、斜率；色块在 `for b in blobs` 内记录 x/y/w/h、中心、前景像素数，再分别标记高度、宽度、比例、窗口、交点间距是否通过。只打印最后通过的候选，会看不到漏检原因。

建议记录层次：无前景 → 无回归候选 → 跨度/斜率拒绝 → 无色块 → 形状拒绝 → 窗口拒绝 → 无横线/间距拒绝 → 连续帧不足 → 已锁定。用失效层次决定改哪个参数。

## 4. 第一步：确认成像和 LAB 阈值

### 4.1 成像先过关

先在理想、阴影、反光三种条件下看原图，静止等待亮度稳定后各观察一段时间。胶带边缘需能分辨；车辆运动时不能严重拖影。若存在失焦、明显抖动或大面积反光，先处理相机固定、焦点、照明/安装方向或曝光，不先扩大 ROI 或降低所有门限。

### 4.2 当前六项阈值与采样位置

![图2：当前LAB三个通道的阈值范围；下方分别示意目标断裂、完整和背景粘连](images/maixcam2_lab_calibration.png)

[图2 SVG](images/maixcam2_lab_calibration.svg) · [图2高清 PNG](images/maixcam2_lab_calibration.png)

当前源码为 `LAB_THRESHOLDS=[[0,56,-5,14,-128,12]]`。这组数值来自现有配置，未提供实测样本或效果记录，不能把它视为通用黑胶带阈值。

实际流程是 BGR→5×5 彩色高斯滤波→RGB 图按 LAB 阈值筛选→单通道二值掩膜→3×3 闭运算→3×3 开运算。横线和竖线特征共用处理后的掩膜，后续 ROI、几何筛选和计数逻辑不变。

阈值顺序为 `[L_MIN,L_MAX,A_MIN,A_MAX,B_MIN,B_MAX]`，采用 MaixPy 标度：L 为 0～100，A/B 为 -128～127。三个通道同时落在范围内才选中；选中像素为白色，其他像素为黑色。代码直接使用 RGB 图的 `binary(LAB_THRESHOLDS)`，见 [官方 API](https://wiki.sipeed.com/maixpy/api/maix/image.html#binary)。不要直接使用 OpenCV 8 位 LAB 编码值。

1. 固定成像条件后，在 MaixVision 或设备“找色块”应用中分别采样横线、竖线内部及邻近背景；正常光照、阴影、反光场景均选多个位置。调参操作见 [官方说明](https://wiki.sipeed.com/maixpy/doc/zh/vision/find_blobs.html)。
2. 记录目标和背景的 L/A/B 范围，以能覆盖横线和竖线样本、尽量排除背景的六项范围作为初值。当前配置只是待复测起点，不是通用推荐值。
3. 将范围填写到 `LAB_THRESHOLDS`，检查本程序高斯滤波后的 `binary_img`：横线应连续、竖线应完整，背景不应大面积变白。原图采样结果需在滤波后的掩膜上复核。
4. L 上限增大可能引入较亮背景；A/B 范围放宽可能引入彩色干扰。一次调整一个通道，重复相同场景，避免只挑某一帧最好看的值。
5. 若目标和背景 LAB 分布重叠，先改善成像或照明；不能保证仅靠阈值解决。完成静态采样后，再复测边缘、远处细线、反光和动态通过。

### 4.3 怎样实际取样与填写阈值

若设备提供“找色块”应用，可按官方流程点击目标、查看 LAB 值，再通过设置中的 L Min/L Max/A Min/A Max/B Min/B Max 微调；不同固件界面需以实机为准。该应用与主程序分开运行，避免同时占用相机。若用 MaixVision 工具，先确认显示的是 LAB 标度，而非 RGB 值。

建议先为“正常光照、阴影、反光”各选3～5处横线内部、竖线内部及邻近背景；每处在画面稳定后重复读数，采样数量仅作为起点。内部样本避开混合边缘；**最细目标和边缘另列验证样本**，不能因为难采样就忽略。自动曝光/白平衡还在变化时，先等待稳定并记录变化情况。

| 参数 | 当前值 | 含义与现场调整依据 |
| --- | --- | --- |
| L_MIN / L_MAX | 0 / 56 | 亮度门限；L 上限增大可能接纳亮一些的胶带，也可能引入地面 |
| A_MIN / A_MAX | -5 / 14 | 绿—红方向；下限增大排除更多偏绿像素，上限减小排除更多偏红像素 |
| B_MIN / B_MAX | -128 / 12 | 蓝—黄方向；当前下限已到标度底部，对偏蓝方向基本不设限，上限限制偏黄像素 |

不能仅因 B 范围较宽就直接收窄：先确认最差光照下胶带样本的分布，再与背景重叠情况比较。L/A/B 的阈值范围是三个区间的交集，某个通道不满足就变黑；扩大一个通道也未必能找回由另一个通道拒绝的目标。

1. 将样本标为 H（横线）、V（竖线）、BG（背景），记录场景、位置、L/A/B、是否位于边缘。每个通道分别查看 H 与 V 的范围，先形成同时覆盖两类目标的候选区间。
2. 单个通道候选下限可取所有合法目标该通道最小值减余量，上限取最大值加余量；再裁到合法标度。余量来自重复取样波动，不能固定照抄某个数字。样本很多时可用分位数辅助，但仍需检查被排除的真实弱目标。
3. 对 BG 样本检验“三个通道是否同时命中”。如果背景也命中，优先收紧能区分它的通道，同时检查是否伤到 H/V 样本。目标与背景完全重叠时，记录为阈值无法区分，而不是继续放宽。
4. 保留原配置，先修改一个上下限并回到同一场景对比。接近临界值时可按1～2个单位微调；这是搜索步长建议，不是传感器精度。每次记录改动、改善和新出现的问题。
5. 把六项值写回标定副本的 `LAB_THRESHOLDS`。最终判据是经过高斯滤波、LAB 筛选后的掩膜表现；工具从原图给出的范围只是起点。

原图中的黑色不保证在所有曝光下具有相同 L；黑胶带也不保证 A/B 恒为0。若要严格比较滤波前后采样，可在标定副本中、`color_img.binary(...)` **之前**临时显示 `color_img`，并只保留这一处显示；不要从已变成黑白的 `binary_img` 采胶带颜色。

### 4.4 判断本轮 LAB 是否可用

按固定顺序复测：正常光照横线 → 最远细竖线 → 阴影 → 反光 → 只有背景的负样本。每个场景同时核对目标连通、目标厚度是否损失、背景是否接触目标，不能只看白色像素总量。图2的三幅掩膜仅用于识别现象，不是这组阈值的真实效果对比。

| 现象 | 先做的检查 | 可尝试的单项调整 |
| --- | --- | --- |
| 两类胶带都消失 | 采样标度、六项顺序、每项下限是否不大于上限 | 根据被拒样本只扩展对应通道；不先放宽几何门限 |
| 横线完整但细竖线断裂 | 对照原图，检查是否仅在边缘/远处发生 | 复核竖线样本范围；必要时在副本比较较小高斯核 |
| 阴影地面与胶带粘连 | 看 BG 是否三个通道都命中 | 若 A/B 有差异则收紧对应区间；否则改善成像或 ROI |
| 高光局部断裂 | 原图中胶带是否已与背景不可分 | 优先调整照明/安装；扩大 L 后必须复查背景 |
| 静态好、运动时失败 | 拖影、曝光变化与细线丢失 | 先复核成像，再做速度回归，不直接减少确认帧数 |

### 4.5 滤波和形态学

| 参数 | 当前值 | 怎么测 | 如何选择 |
| --- | --- | --- | --- |
| `BLUR_KERNEL_SIZE` | 5 | 对同场景比较 3、5、7 的二值效果 | 使用能抑制噪点又保住最细目标的最小合适正奇数核 |
| `MORPH_KERNEL_SIZE` | 3，先闭运算后开运算 | 在标定副本比较 1、3、5；重点看细竖线是否消失、相邻物体是否合并 | 闭运算补小缺口，开运算去小噪点；核过大会损失细线 |
| `BINARY_WHITE_THRESHOLDS` | `[[200,255]]` | 确认输入确实是 0/255 的二值图 | 通常保持；这不是原始图像的黑胶带颜色阈值 |

当前颜色标定只修改 `LAB_THRESHOLDS`；`BINARY_WHITE_THRESHOLDS` 继续用于掩膜白色前景检测，无需跟随胶带颜色调整。

本阶段通过条件：测试场景下横线连续、竖线可见、背景前景不过度粘连；保留失败图，不能只保留成功图。

## 5. 第二步：测量主 ROI 与横线 ROI

### 5.1 主 ROI 四个比例

手推车辆覆盖预期姿态范围，在原图记录有用目标的最左、最右、最高、最低位置，同时标出车体/线缆/无关背景区域。主 ROI 覆盖目标运动包络并留出抖动余量，且尽量避开固定干扰。

若确定边界为左 x0、上 y0、右边界 x1、下边界 y1（右下不包含）：

```text
M_ROI_X_RATIO = x0 / W
M_ROI_Y_RATIO = y0 / H
M_ROI_W_RATIO = (x1-x0) / W
M_ROI_H_RATIO = (y1-y0) / H
```

当前 `(0.05,0,0.90,0.55)` 得到 `[16,0,288,132]`。写回比例后按代码的 `int()` 重新计算整数坐标，确认无越界、宽高为正，且横线 ROI 完整落在主 ROI 内。

### 5.2 横线 ROI 两个比例

在全部允许姿态下记录横线带的 y 上下界，不只记录中心；倾斜时左右端高度不同。选检测带时既要包含足够长的真实横线，也要避免上方竖线占据太多前景。

```text
H_ROI_Y_RATIO = (检测带起始y-main_top) / main_height
H_ROI_H_RATIO = 检测带高度 / main_height
```

当前是 `int(132×0.48)=63`、`int(132×0.35)=46`，而不是 `240×0.48/0.35`。若转弯时横线完全离开 y=63～108，先修改检测带；调低回归面积门限不能找回 ROI 外的线。

主 ROI 变化后，重新检查两个方向采样点是否被边界截断；若实际间距不再是 120，`head` 的比例也会改变。

### 5.3 坐标读数与整数边界核对

例：主 ROI 的右边界304不包含在内，最后有效列是303；横线 ROI 的下边界109不包含，最后有效行是108。判断目标“在线框内”时，应以源图像素坐标为准，而不是彩色边框覆盖到的显示像素。

若预览中的有效图像区域从 `(u0,v0)` 开始，显示宽高为 `(Wd,Hd)`，鼠标点为 `(u,v)`，则 `x=(u-u0)×320/Wd`、`y=(v-v0)×240/Hd`。先扣除黑边和界面工具栏；若显示有裁剪或旋转，需要先还原该变换。没有明确预览映射时，保存原尺寸图再测量。

写回比例后核对：`0≤main_left<main_right≤320`、`0≤main_top<main_bottom≤240`，且 H_roi 完全在主 ROI 内。合法姿态下横线不应仅擦过检测带一两个像素；保留空间余量，但不要大到让竖线前景占主导。

## 6. 第三步：确认横线筛选与误差零点

### 6.1 横线门限

| 参数 | 当前值 | 需要记录 | 定值依据 |
| --- | --- | --- | --- |
| `L_min_area` | 100 | 回归区域前景范围、目标/噪声能否生成候选 | 在最弱合法目标仍能检测的条件下尽量抑制小干扰 |
| `L_min_pixels` | 80 | ROI 内属于目标的白像素规模与候选稳定性 | 与面积分开评估，不用线长代替像素数 |
| `L_min_length` | 60 | 所有候选的 `abs(x2-x1)` | 低于最短合法水平跨度，并高于可区分的短干扰 |
| `MAX_H_slope` | 0.45 | `abs(dy/dx)` 与允许最大车体姿态 | 覆盖合法图像斜率并保留适当余量 |

`0.45` 约为图像水平夹角 24.2°，不是舵机角度。回归前置门限拒绝的目标不会出现在候选列表中：必要时在同一静态场景临时降低一个前置门限进行对照，再恢复；不能通过空候选反推目标具体面积。

当前代码按通过筛选的候选长度选最长者。若线明明存在却拟合到其他前景，应先收紧场景/ROI 或处理粘连，而不是一味放宽门限。面积与像素参数的精确定义、返回值以当前固件对应的 [官方图像 API](https://wiki.sipeed.com/maixpy/api/maix/image.html) 为准。

### 6.2 `Target_Y=82.0`

把车放到**实际希望保持的横向位置和朝向**，在多个场地位置分别采集建议 100 帧。只对横线正确且有效的帧记录 `line_y_at_trigger`，同时记录总帧数与有效帧数，不能把无效帧记成零。

以有效 y(208) 的中位数作为候选 `Target_Y`。记录 P05/P95 和极值反映抖动；重复摆放后零点应一致。若不同位置差异显著，先查地面、光照、安装和拟合偏差，不机械取总体平均。

位置误差 `pos=y(208)-Target_Y`：正值表示线在图像中比参考位置更靠下；它不直接表示车应左转还是右转。

### 6.3 `HEADING_SAMPLE_HALF_WIDTH=60`

当前左右 x=148、268，`head=y(268)-y(148)`。在直行理想姿态记录零点，再分别让车发生小幅左、右偏转，确认误差变化趋势。`head` 的单位是像素，不是角度。

跨度越大，同一斜率下高度差越大，也更依赖拟合线外推。观察真实支持横线是否覆盖这两个采样位置；当前代码不会禁止在拟合端点外取样。如果理想车姿下 `head` 持续不接近零，检查相机滚转/安装方向；当前没有可直接调的方向零偏参数，不要靠改 `Target_Y` 消除方向偏差。

控制误差容限应先由车辆允许偏差确定。可固定姿态、用尺子做已知的小幅平移，记录 pos 改变量，建立**该局部工作范围**的像素/毫米关系；存在透视时不能把它推广到全画面。改变相机、分辨率或采样跨度后需重新检查控制增益。

### 6.4 手算一帧，确认程序与理解一致

图3C的独立演算示例为 `y(x)=90+0.15(x-208)`：`y(148)=81`、`y(208)=90`、`y(268)=99`，所以 `pos=90-82=8 px`，`head=99-81=18 px`。这些是演示数字，不填写为实测结果。实机上选择一帧拟合正确的图，代入实际端点手算一次，再与显示值比较；串口只保留一位小数。

零点复测建议至少重复摆车3次，各采一段稳定帧；先排除错线，再记录有效帧数、中位数、P05/P95和极值。允许的波动限值应预先填写。pos 与 head 分开判断：位置零点变化只改位置标定；方向持续偏移先检查安装，不能用 `Target_Y` 补偿方向偏差。

## 7. 第四步：确认动态裁剪与竖线参数

![图3：上方按斜线逐列清零；左下为裁剪后色块尺寸；右下为位置和方向误差的独立演算示例](images/maixcam2_geometry_calibration.png)

[图3 SVG](images/maixcam2_geometry_calibration.svg) · [图3高清 PNG](images/maixcam2_geometry_calibration.png)

### 7.1 先调裁剪，再量色块

```text
每列横线高度 y(x) = y1+(x-x1)×dy/dx
cut_y(x) = max(main_top, min(int(y(x))-V_TO_LINE_GAP, main_bottom))
从 cut_y(x) 到主 ROI 底边的像素清零
V_roi_height = min(main_height, max(MIN_V_ROI_HEIGHT, 所有列 cut_y-main_top))
```

`V_roi` 是包围矩形；其中斜线下方部分仍为黑色。`MIN_V_ROI_HEIGHT=24` 只给矩形高度兜底，不会把已清零的目标恢复。丢线时不按旧线裁剪，高度回到最小值，交点判断仍要求本帧横线有效。

测 `V_TO_LINE_GAP=3`：看 `V_binary_img` 中是否残留横线粗带并与竖线粘连。若残留，逐步增大；若竖线截得过短，检查是否过大。可从“横线半厚度＋拟合偏差余量”估计起点，但最终看实际裁剪图。每次改变它，都要重新测 h、像素数和交点间距。

### 7.2 竖线形状门限

以远近、斜视、阴影、反光下的真地标为正样本，以孤立黑点、接缝、宽块、无关竖条为负样本。统计**裁剪后**的候选，而不是原图整条胶带。

| 参数 | 当前值 | 测量与选择方法 |
| --- | --- | --- |
| `MARK_MIN_AREA` | 50 | 记录外接框面积 w×h；阈值低于最弱合法目标，并尽量排除小块 |
| `MARK_MIN_PIXELS` | 35 | 记录色块实际前景像素数；与 w×h 不同，空洞、斜线都会使它更小 |
| `MARK_MIN_HEIGHT` | 14 | 记录 h 的最小值与低分位数；保留最短合法地标 |
| `MARK_MAX_WIDTH` | 28 | 记录 w 的最大值与高分位数；必须容纳透视、倾斜造成的增宽 |
| `MARK_MIN_ASPECT_RATIO` | 1.8 | 记录 h/w；真地标与干扰重叠时，不能只靠此条件区分 |
| `MAX_JUNCTION_GAP` | 12 | 记录 `d=abs(b.y()+b.h()-int(y(b.cx())))`；覆盖合法间距而排除悬空干扰 |

最小门限一般设在合法样本低端以下一点，最大门限设在合法样本高端以上一点；余量以重复摆放与动态抖动为依据，不固定套用一个百分比。分位数用于选起点，最终仍要查最差合法样本及误检样本。

图示例：色块 y=40、h=39，底边 y+h=79，最后有效像素行78；横线 y=82，所以 d=3。裁剪本身就制造间隔，不能把 `MAX_JUNCTION_GAP` 设为零。横线倾斜、色块具有宽度时，矩形底边也不一定等于中心列的裁剪高度，间距不能只凭 `V_TO_LINE_GAP` 推算。

色块搜索还使用 `merge=True, margin=2`，可能把相邻碎片合并；合并后的 w/h/像素数应一并观察。初期保持这些搜索选项不变，发现合并导致具体失效后才单独比较。

### 7.3 触发中心与窗口半宽

把车放在“希望视觉地标被确认”的位置，记录色块 cx，候选 `Mark_trigger_x_ratio=cx/W`。当前 0.65→208。该参数同时改变位置误差采样点和方向采样中心，修改后必须复核 `Target_Y`。

`MARK_TRIGGER_HALF_WIDTH=34` 控制中心允许范围 174～242。手推地标通过窗口，记录第一次满足、连续满足、最后满足的帧。太窄容易驻留不足；太宽会提早确认，还可能让相邻地标之间没有清空期。旧参数 `Mark_half_w=34` 没有使用，不调它。

触发线不是车辆停车线：地标从窗口边缘进入，累计确认后才发计数，还有串口、控制和制动延迟。最终触发位置要在计划速度下量实际车辆位置来校正，而非仅让示意图上的中心对齐。

### 7.4 记录“在哪个条件被拒绝”

先检查 `find_blobs` 是否返回候选；面积或像素门限已经拒绝的目标不会进入后续循环。对返回的每个候选，按源码顺序记录 `w>0 → h≥14 → w≤28 → h/w≥1.8 → |cx-208|≤34 → 横线有效 → d≤12`，只给第一个未通过条件标记失败，便于定位主要原因。

形状和窗口通过后，`mark_in_window` 就可能为真；即使间距 d 不合格，也可能阻止解除锁定。因此“没有计数”和“窗口已清空”不是同一件事。现场记录不能只保存最终画出的红框，还应包含被间距条件拒绝的候选。

## 8. 第五步：用实际运行速度确认计数时序

![图4：18帧演示中第3帧计数，第10帧丢线打断清空，第15帧解除锁定，第18帧再次计数](images/maixcam2_timing_calibration.png)

[图4 SVG](images/maixcam2_timing_calibration.svg) · [图4高清 PNG](images/maixcam2_timing_calibration.png)

图4每格是本帧处理后的状态；1表示条件成立或状态有效，0表示不成立。连续数与 count 是整数。第6～9帧虽已清空4帧，第10帧丢线仍将清空连续数归零；第11～15帧必须重新积累。该图使用合成输入执行源码中的计数片段，不代表板端帧率测试。

先人工慢推验证状态，再测试低速、额定速度、最高计划速度。每个速度建议至少通过 20 次，并分别记录漏计、重复计、误计与首次触发位置；建议次数不代表已达到统计可靠性或比赛验收要求。

| 场景 | 当前程序应有的行为 |
| --- | --- |
| 合格交点只出现连续2帧，然后消失 | 不计数；连续确认归零 |
| 合格交点连续3帧，初始未锁定 | 第3帧计数+1并锁定 |
| 同一地标留在窗口内很多帧 | count 不再增加；不是每3帧加一次 |
| 锁定后横线有效、窗口无合格竖线连续4帧 | 仍锁定 |
| 上述条件连续达到5帧 | 解锁，允许下个交点重新确认 |
| 短暂丢横线 | 不新增计数，不解锁；确认和清空连续数被打断 |
| 窗口还有形状合格竖线，但交点间距不合格 | 不计数，但可能仍阻止解锁 |
| 旧地标充分离开、解锁后又返回 | 可能再次计数；当前算法没有地标身份识别 |

分别统计每次通过的**最长连续候选帧数**与两个地标之间的**最长连续有效清空帧数**。只算“窗口总共出现过多少帧”不够，中途一帧失败会打断确认。

粗略规划：有效处理频率为 f 时，可按确认驻留时间不少于 `3/f`、清空间隔不少于 `5/f` 留预算，并增加余量。第一次到第三次采样的时间差约为 `2/f`，进入窗口到确认还受采样相位影响，因此不能把这些公式当精确时延。

若地标中心近似匀速以 vx 像素/秒移动，窗口驻留约 `2×34/|vx|` 秒；前提是整个过程都满足形状和交点条件。近似同向移动、地标中心间距为 D 像素时，清空时间可粗估为 `max(0,D-68)/|vx|`。透视、抖动、两个地标同时入窗都会破坏此近似，最终以逐帧记录为准。

若最高速度漏计，先区分图像模糊、几何漏检、实际循环卡顿、窗口太窄；确认是时序不足后，再比较加宽窗口、降低速度或减少确认帧数的取舍。减少确认/解除帧数会提高噪声触发或重复计数风险，必须重做负样本和抖动测试。

每次动态测试先记进入路线前的 `count_start`，结束后记 `count_end`，用差值与人工真值比较；不用累计总数直接当本轮检测数。建议由另一人或独立录像记录真值、每个地标通过时刻和触发位置。暂停、倒车和旧地标重新进入需单列，避免把算法的重新计数机制误记为单次通过重复计数。

## 9. 性能、串口与最终验收

记录完整循环耗时，包含相机读取、图像处理、串口和显示；统计均值、P95、最大值以及有效横线帧比例。用设备上的单调时钟测本机时差，控制端另测完整报文接收间隔；两个不同设备的时钟未同步时不能直接相减求端到端时延。

分别测试“开预览/开临时日志”和“正式运行配置”。详细日志会影响速度，几何标定可开，速度验收应使用计划部署的日志量。相机标称 FPS、MaixVision 预览刷新率和有效控制更新率是不同量。

串口当前为 `valid,pos,head,count` 四字段、以换行结束。`valid=0` 时零误差只是占位值；下位机不能当作车已居中。累计 count 不应每条报文重复相加。视觉重启会从0开始，控制端应识别计数回退并重新建立阶段基准。串口超时和丢线策略须按既有控制约定验证。

| 验收项 | 建议执行方式 | 必须记录的结果 |
| --- | --- | --- |
| 静态误差 | 各姿态/光照建议100帧，多次重新摆车 | 有效率、pos/head 中位数与 P05/P95、错线次数 |
| 动态地标 | 各速度至少20次起步，并含最近间距地标 | 真值数、漏计/重复/误计、触发位置范围 |
| 负样本 | 无地标路线、接缝、阴影、反光、干扰块 | 误触发次数与对应截图 |
| 暂时失效 | 短暂遮挡、丢线、串口中断/进程退出 | 是否停用旧误差、是否错误解锁或重复计数 |
| 连续运行 | 按比赛时长与工程余量设定 | 最大卡顿、异常/重启、计数和资源是否异常 |
| 离线应用 | 打包、安装、关闭在线调试、重新上电 | 正确入口与参数、正常出图和报文、计数初值 |

“20次没有失败”只能说明这些测试中没有观察到失败，不能证明百分之百可靠。最终有效率、误差、最大延迟、允许漏计率与测试时长应填写明确限值，再判定通过。对停车计数，可将“规定回归测试内漏计/重复/误计均为0”作为候选工程门槛，但仍需结合题面确认。

打包时确保应用根目录含 `main.py`；图表、标定记录和电脑端绘图脚本不用打包进车辆应用。部署说明见 [MaixVision 官方文档](https://wiki.sipeed.com/maixpy/doc/zh/basic/maixvision.html)。

## 10. 现场记录与快速定位

[参数记录 CSV](maixcam2_parameter_record.csv) 已同步当前 LAB 六项阈值、形态学启用状态及几何参数；实测列保持空白。可用 Excel 打开：先填硬件/环境，再填实测范围、最终值和复测结论。每次改变代码参数后核对“当前初值”列。另按下面的字段保存每轮测试，不填虚构测试数据：

```text
测试编号、日期、代码/参数版本、场景编号、光照、相机安装、曝光模式、速度
总帧数、有效横线帧数、错线帧数、pos/head中位数与P05/P95
候选色块w/h/像素数范围、交点间距范围、连续候选帧数、连续清空帧数
真值地标数、count增量、漏计、重复计、误计、触发位置范围
循环均值/P95/最大耗时、控制端最大报文间隔、失败截图、结论
```

| 现象 | 优先检查 |
| --- | --- |
| 原图有线，二值图没有 | 曝光/反光、LAB范围、模糊核、开运算是否抹掉细线 |
| 二值图有横线，提示 line:lost | 是否在 H_roi 内、回归门限、水平跨度与斜率 |
| 横线有效，竖线不见了 | 主 ROI 边界、逐列裁剪间隔、裁剪后的高度/宽度/比例 |
| 色块框存在但不计数 | 窗口位置、交点间距、连续3帧条件、当前锁定状态 |
| 第二个地标漏计 | 前一地标是否完成连续5帧有效清空；窗口是否过宽 |
| 静态正常，快速运动失败 | 拖影、连续候选帧数、完整循环长尾、图像预览/日志开销 |
| 数值很稳定但车辆跑偏 | Target_Y 标定姿态、误差反馈符号、方向零偏与控制端处理 |

### 10.1 哪些修改需要重新标定

| 修改内容 | 至少重新核对 |
| --- | --- |
| 曝光、白平衡、照明、胶带或地面 | LAB 六项范围 → 连通性 → 色块尺寸与像素数 → 动态计数 |
| 相机高度/角度、分辨率 | LAB、全部 ROI、横线筛选、pos/head 零点、裁剪与时序 |
| 高斯核、LAB 阈值、形态学开关或核尺寸 | 细线厚度/连通 → 横线拟合 → 裁剪后 h/w/像素数/d |
| 主 ROI、横线 ROI、触发中心 | 采样点是否被截断、横线是否正确、Target_Y、触发位置 |
| 裁剪间隔 | 最短竖线 h、有效像素数、交点间距，随后重测漏计 |
| 窗口半宽、确认/解除帧数、车速 | 最短驻留、相邻地标清空、触发位置、重复/漏计 |

### 10.2 标定完成时应留下什么

- 一份最终参数记录，包含源码版本/哈希、固件版本、相机设置与安装尺寸；每项有证据文件和复测结论。
- 一组正常/阴影/反光、近/远、极限姿态的原图及处理图，包含失败样本与最终解决方式。
- 一份静态误差记录和动态逐次记录，写明预设限值、实际结果、通过/未通过；未测项目写“未测”。
- 一份启动复测记录：部署相同参数后重新上电，确认默认画面、报文、零点、计数和最高速度表现。
