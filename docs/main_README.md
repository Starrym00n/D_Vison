# main.py README

**[code/main.py](../code/main.py) 是 MaixCAM2 巡线与地标计数程序。** 输入为相机实时图像；输出为位置/方向像素误差、累计地标数，以及叠加识别结果的显示画面。程序通过UART向下位机发布结果，下位机负责电机、舵机、控制算法、任务阶段与停车。

本文说明该文件的运行环境、结构、处理逻辑、结果字段、串口协议与异常行为。详细参数测定、ROI示意图及逐步教学统一见 [MaixCAM2参数实测与ROI标定方案](MaixCAM2参数实测与ROI标定方案.md)。当前图像为 **320×240**；参数是工程初值，实车性能仍需验证。

## 2. 第一次运行

1. 固定相机支架，使画面能看到横线和其上方的竖线。使用实际场地与胶带，先让电机保持停止。
2. 记录板卡、固件、MaixPy、MaixVision 版本和安装高度。板端需能导入 `maix`、`cv2`、`math`；项目没有声明已经验证的最低版本。
3. 连接设备，在 MaixVision 中打开 `code/main.py`，停止旧程序，选择“运行当前文件”。电脑终端直接运行整份脚本不能代替板端运行。参照 [MaixVision 官方说明](https://wiki.sipeed.com/maixpy/doc/zh/basic/maixvision.html)。
4. 检查控制台是否报错，确认图像持续更新。UART 初始化在首次显示之前，串口或引脚错误也可能导致没有画面。
5. 看蓝色拟合线是否贴着真实横线，底部是否出现 `pos/head`。`line:lost` 或 `pixel:invalid` 表示本帧横线无效，按参数测定方案检查黑白图与 ROI。
6. 手推验证计数通过后，再与下位机做低速联调。每次改参数都要保存、停止旧程序、重新运行；只保存不会改变正在运行的参数。

### 串口接线

| 项目 | 当前源码配置 |
| --- | --- |
| 端口、波特率 | `/dev/ttyS4`，115200 |
| 发送端 | A21 映射为 UART4_TX，接下位机 RX |
| 接收端 | A22 映射为 UART4_RX；程序当前没有接收处理 |
| 地线 | 两端 GND 相连 |

接线前核对实际板卡引脚与两端逻辑电平；数据位、校验位、停止位按安装版本的默认设置核对，因为源码只显式传入端口和波特率。接口参照 [官方 UART 文档](https://wiki.sipeed.com/maixpy/doc/zh/peripheral/uart.html)。

## 3. 默认配置

| 项目 | 当前值及含义 |
| --- | --- |
| 颜色筛选 | `LAB_THRESHOLDS=[[0,56,-5,14,-128,12]]` |
| 预处理 | 高斯核5×5；矩形核3×3，先闭运算再开运算 |
| 主 ROI | `[16,0,288,132]`：x=16～303，y=0～131 |
| 横线 ROI | `[16,56,288,35]`：x=16～303，y=56～90 |
| 横线筛选 | 面积100、白像素80、水平跨度至少60、绝对斜率至多0.45 |
| 位置零点 | `Target_Y=73.0`，仍需在理想车姿下实测 |
| 方向采样点 | x=148、268，相距120 px |
| 地标触发窗口 | 中心x=208，半宽34；允许 `174≤cx≤242` |
| 裁剪与接近条件 | `V_TO_LINE_GAP=10`；`MAX_JUNCTION_GAP=12` |
| 竖线形状 | 高度≥14、宽度≤28、高宽比≥1.8 |
| 计数去重 | 候选连续3帧确认；已计数地标被跟踪到窗口外且横线有效，累计5帧后解锁 |

完整常量表及测定方法见参数测定方案。`Mark_half_w` 当前未被使用；窗口由 `MARK_TRIGGER_HALF_WIDTH` 控制。ROI、触发中心和形态学核在循环前计算，运行期间不会自动重载参数。

## 4. 程序结构与每帧处理流程

脚本依次执行：定义参数并计算ROI → 初始化相机、显示、UART及计数状态 → 在 `while not app.need_exit()` 中处理图像 → 正常离开循环后关闭串口。每一轮主要处理如下：

```text
相机取图 → 彩色高斯滤波 → LAB筛选 → 转成单通道黑白图
→ 闭运算补小缺口 → 开运算去小噪点 → 主ROI外清零
→ 横线ROI内回归 → 筛水平跨度/斜率 → 选最长合格候选
→ 计算位置与方向误差 → 沿拟合横线逐列裁掉横线及下方
→ 找竖线色块 → 筛形状/窗口/交点间距 → 连续确认与计数
→ 发送串口 → 显示原图和识别标注
```

黑胶带经颜色筛选后，在掩膜中应是**白色**。`BINARY_WHITE_THRESHOLDS=[[200,255]]` 用于找掩膜里的白色，与原图的 LAB 六项阈值用途不同。代码没有显式固定曝光、白平衡或帧率；更改成像设置后需要重测颜色阈值。

横线回归使用 `robust=True`、两个方向的采样步长均为1；`L_min_length` 检查的是 `abs(x2-x1)`，不是斜线总长。最长候选也可能拟合到干扰，仍须对照原图检查。

## 5. 显示输出与误差定义

| 标注或文字 | 含义 |
| --- | --- |
| 绿色大框 / 绿色水平线 | 主 ROI / 位置参考高度 Target_Y |
| 蓝色框 / 蓝色线 | 横线搜索区域 / 拟合结果 |
| 两个绿色小方块 | 方向误差的左右采样点 |
| 红色大框 / 红色窄框 | 动态竖线搜索 ROI / 触发窗口，二者都不是检测结果 |
| 紧贴竖线的红框 / 交点红色小方框 | 本帧选中的候选 / 已连续确认的交点 |
| pos | 横线在触发横坐标处相对参考高度的偏差，单位px |
| head | 右采样点y减左采样点y，单位px，不是角度 |
| angle / rho | 图像线角度（度，范围 `(-90,90]`）/ 回归距离参数；均未发串口 |
| mark / count / lock | 本帧连续确认状态 / 累计次数 / 是否锁定 |
| line:lost / pixel:invalid | 没有合格横线，当前误差不能使用 |

图像原点在左上角，x向右、y向下。当前参数下，设拟合线在横坐标x处的高度为 `y(x)`：

```text
pos  = y(208) - 73.0
head = y(268) - y(148)
```

例如中心高度81、左点72、右点90，则 `pos=8 px`、`head=18 px`。正号只表示图像方向，不能直接换算为舵机应左转或右转。三个采样点都必须在主 ROI 内，且拟合位置附近的二值图有足够白像素；仍未要求采样点位于回归线端点之间。

## 6. 地标计数状态机

1. 在动态 V_roi 中找色块，经过面积、像素、高度、宽度、高宽比筛选。
2. 色块中心进入触发窗口，并且当前横线有效。
3. 色块底边与横线在该中心处的纵向距离满足 `abs(b.y()+b.h()-int(y(b.cx())))≤12`。多个候选合格时选距窗口中心最近的一个。
4. 同一候选的交点坐标相邻帧变化不超过 `MARK_MAX_STEP=16` 像素，连续3帧满足条件且未锁定，count加1、lock置1。mark可以持续为1，但不会持续加数。
5. 锁定后以最近的横坐标跟踪已计数地标；观测到其中心越过触发窗口并超出 `MARK_RELEASE_MARGIN=4` 像素、横线有效时，累计5帧后解锁。出窗后即使暂时未检出色块，也沿用最后观测位置累计；横线无效或最后位置回到边界内则清零释放计数。

丢横线会打断确认和释放连续数，但不会清空累计计数或主动解锁。已计数地标若在跟踪到出窗前被遮挡、漏检，或单帧位移超过16像素，可能一直锁定并漏计后续地标；跟踪若误关联其他色块，也可能改变释放时机。算法不识别地标身份：充分离开后返回可能再计一次。

## 7. 结果字段与串口协议

### 本机结果字典

每轮构造一次 `vision_result`。该字典保存在进程内，没有自动写入文件或通过网络发布。

| 字段 | 含义与无效值 |
| --- | --- |
| `line_valid` | 当前是否有合格横线，布尔值 |
| `position_error_px` | 位置误差；横线无效时为None |
| `heading_error_px` | 方向像素差；横线无效时为None |
| `line_angle_deg` | 横线图像角度；横线无效时为None |
| `junction_confirmed` | 当前是否达到连续确认帧数，布尔值 |
| `junction_event` | 本帧是否新增一次计数，仅事件帧为True |
| `junction_count` | 本次进程累计地标计数，整数 |
| `junction_xy` | 连续确认后的当前交点坐标元组；未确认时为None |

### UART输出

每帧发送一行ASCII文本，4个字段用英文逗号分隔，末尾为实际回车换行。下方用 `\r\n` 表示这两个字符：

```text
valid,pos,head,count\r\n        ← 字段说明，这一行不会发送
1,-12.5,3.2,2\r\n              ← 横线有效
0,0.0,0.0,2\r\n               ← 横线丢失，累计数保留
```

接收端按换行组包，检查4个字段，处理一次收到半行或多行的情况。`valid=1` 才能使用误差；`valid=0` 时两个0只是占位，不能解释为居中。发送频率由整轮耗时决定，源码没有固定周期，接收超时也必须由下位机处理。

count是进程启动以来的累计值，**不能每收到一行就再加到自己的计数器里**。例如阶段起点收到5，后来收到8，阶段通过数为 `8-5=3`。视觉端没有阶段管理、串口清零命令或计数持久化；重启归零后，下位机需重新建立基准。仅凭四字段无法保证辨认所有重启情形，联调时应测试重启恢复。

串口只发送上述四字段，不发送角度、事件标志、交点坐标或锁定状态。协议中没有时间戳、序号和校验字段。

## 8. 异常处理与使用限制

| 情况 | 当前程序行为与接收端要求 |
| --- | --- |
| 横线丢失 | 本轮误差无效，发送valid=0及两个0占位；保留count |
| 引脚映射失败 | err.check_raise抛出异常，不能进入正常处理循环 |
| UART写入异常或长度不足 | 关闭串口并抛出异常，停止正常更新，不自动重发 |
| 正常退出 | app.need_exit()为True后离开循环，执行serial_dev.close() |
| 其他运行异常 | 没有覆盖整个循环的统一异常恢复；下位机需检测接收超时 |
| 程序重启 | 计数与锁定状态重新初始化，不恢复上次进度 |

程序没有物理距离换算、地标身份跟踪、接收指令、PID、停车执行或任务阶段管理。地标需出现在横线上方；错误拟合、背景粘连、遮挡及高速下连续帧不足都可能影响结果。控制方向、容许速度和停车精度应以整车测定为准。

## 9. 检查与部署

### 框架逻辑复核结论

按当前源码，采图、预处理、横线筛选、像素支撑检查、竖线裁剪与候选确认、计数去重、无效帧串口占位和显示形成完整视觉输出链；下位机按 `valid,pos,head,count` 接收并承担控制、阶段管理和接收超时处理时，框架具备完成视觉端任务的逻辑条件。`code/main_dual_roi.py` 未纳入本次入口检查。

电脑端 `python -m unittest discover -s tests -v` 的13项测试通过，覆盖计数状态、误差计算和UART异常边界。测试执行源码片段，但未运行MaixPy图像算法、实际相机和串口；不能据此认定板端识别率、实时性或停车精度达标。正式验收仍需按参数测定方案验证目标板 API、光照/姿态、最高车速下的连续帧与出窗跟踪、相邻地标、通信超时及重新上电。若目标在出窗前失踪导致锁定不释放，须先解决现场可观测性或跟踪策略，再用于连续计数。

电脑端在项目根目录检查语法，不会启动相机：

```powershell
python -c "import ast,pathlib; ast.parse(pathlib.Path('code/main.py').read_text(encoding='utf-8-sig')); print('syntax PASS')"
```

预期输出 `syntax PASS`；这只能证明语法可解析。交付前还要按 [参数测定方案](MaixCAM2参数实测与ROI标定方案.md) 完成板端颜色、ROI、计数、串口、动态和重新上电测试。

部署时在 MaixVision 中以 `code/` 为应用目录检查 `main.py`、`app.yaml` 和 `app.png`，重新打包安装。`code/dist/` 中的ZIP是已有产物，不能保证包含这次参数；安装后重新上电，核对屏幕与串口。操作参照 [官方应用打包说明](https://wiki.sipeed.com/maixpy/doc/zh/basic/maixvision.html)。
