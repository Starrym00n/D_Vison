# MaixCAM2 双 ROI 视觉端使用与参数标定

对应源码：[code/main_dual_roi.py](../code/main_dual_roi.py)。

## 1. 框架检查结论与职责

当前代码具备巡线误差计算、交点识别与累计计数、失效标志和串口输出，可进入 MaixCAM2 实车联调。框架与双方分工一致，但不等于已完成实机验收。

| 视觉端负责 | 下位机负责 |
| --- | --- |
| 采集、二值化、横线拟合 | 电机、舵机和 PID |
| 输出位置误差、方向误差、横线有效标志 | 根据安装方向确定反馈正负号，处理丢线与通信超时 |
| 检测交点并累计 `count` | 巡线、泊车、出库的阶段切换 |
| 每帧发送四字段数据 | 恢复巡线时记录基准，按阶段增量定位 |

已检查：Python 语法、单文件无函数封装、正常连续确认与解除锁定、累计计数逻辑。此前合成样例验证过正负斜率下逐列裁剪，以及先检查交点条件再选择最近候选。合成测试不是 MaixPy 板端识别测试。

仍需实测：固件与 MaixPy 兼容性、真实胶带和反光、运行帧率、计数准确率、串口物理连接及完整出入库衔接。已知计数局限见第 8 节。本次 README 不修改视觉算法。

## 2. 在 MaixCAM2 上运行

1. 固定相机、镜头方向和安装高度，准备实际使用的白色场地与黑胶带。
2. 记录设备固件、MaixPy 版本、相机型号、分辨率和安装姿态。当前源码使用 `320 × 240`、`FMT_BGR888`，依赖板端 `maix`、`cv2` 和标准库 `math`。
3. 用 MaixVision 连接 MaixCAM2，打开 `code/main_dual_roi.py`，选择运行当前文件。本脚本不依赖其他项目 Python 文件或模型。不要误运行旁边尚在开发的 `code/main.py`。
4. 查看板载屏幕或 MaixVision 预览，确认有图像、ROI 和底部状态文字。
5. 接串口助手检查数据，再交给下位机联调。首次标定采用静置或手推方式，避免错误识别直接驱动车辆。

MaixVision 支持单文件运行和通过 `disp.show()` 预览设备图像；电脑端安装库不代表板端环境已具备相同模块，具体操作见 [MaixVision 官方说明](https://wiki.sipeed.com/maixpy/doc/zh/basic/maixvision.html)。相机设置与设备支持情况见 [MaixPy 摄像头文档](https://wiki.sipeed.com/maixpy/doc/zh/vision/camera.html)。

### 串口接线

| MaixCAM2 | 对端 | 用途 |
| --- | --- | --- |
| A21 / UART4_TX | 下位机或 USB-UART 的 RX | 视觉数据输出 |
| GND | GND | 共地 |
| A22 / UART4_RX | 对端 TX，可不接 | 代码配置了 RX，但当前不接收命令 |

配置为 `UART_DEVICE="/dev/ttyS4"`、`UART_BAUDRATE=115200`，默认 `8N1`。确认两端逻辑电平兼容，不能把 RS-232 电平直接接到板上 UART。UART4 引脚映射依据 [MaixPy 官方 UART 示例](https://wiki.sipeed.com/maixpy/doc/zh/peripheral/uart.html)。

## 3. 每一帧做什么

```text
相机图像 → 灰度 → 高斯滤波 → 反相二值化 → 闭运算、开运算
  → 主 ROI 外清零
  → 横向 ROI 回归、过滤跨度与斜率、选择最长候选
  → 计算位置误差和方向误差
  → 复制二值图，按横线方程逐列清除横线及其下方
  → 查找竖线色块，先检查形状、窗口、交点距离，再选最近者
  → 连续确认、锁定计数、窗口清空后解除锁定
  → 串口发送 + 显示结果
```

坐标原点在整幅图像左上角，x 向右、y 向下，ROI 格式为 `[x, y, w, h]`；w、h 是宽高，不是右下角坐标。

```text
(0,0) ───────────────────────────────────→ x
  │   ┌───────── 主 ROI ─────────────────┐
  │   │                 │ 库边竖线      │
  │   │                 │               │
  │   │   横向检测带    ╱                │
  │   │──────────────╱──── 道路横线      │
  │   │           ╱                     │
  │   └─────────────────────────────────┘
  ↓ y
```

竖线检测图的有效下边界跟随斜线，不是一个水平矩形。屏幕上的红色竖线 ROI 框只是包围范围，检查实际裁剪效果需切换到 `vertical_binary_img`。

| 屏幕内容 | 含义 |
| --- | --- |
| 绿色大框 / 水平线 / 小方框 | 主 ROI / 目标高度 / 左右采样点 |
| 蓝色框与线 | 横向 ROI 与选中的拟合线 |
| 红色框 | 竖线 ROI、触发窗口、选中的色块或确认交点 |
| `pos`、`head` | 位置误差、方向误差，单位均为像素 |
| `angle`、`rho` | 拟合线调试信息；不通过当前串口协议发送 |
| `mark`、`count`、`lock` | 当前交点是否确认、累计次数、计数是否锁定 |
| `line:lost`、`pixel:invalid` | 没有有效横线，误差不可用于控制 |

## 4. 串口协议与阶段计数

```text
valid,pos,head,count\r\n
1,-12.5,3.2,2\r\n
0,0.0,0.0,2\r\n
```

这里的 `\r\n` 表示实际回车换行字节，不是四个可见字符。

| 字段 | 类型与语义 |
| --- | --- |
| `valid` | 0 或 1；为 0 时必须忽略两个误差 |
| `pos` | 一位小数，横线在触发中心处的 y 减去 `TARGET_LINE_Y` |
| `head` | 一位小数，右采样点 y 减去左采样点 y，不是角度 |
| `count` | 非负整数，视觉进程启动后累计确认的交点次数 |

每帧发送一次，无固定发布频率、校验和、ACK、时间戳或阶段字段。接收端按换行缓存完整行，检查四字段与数值格式，处理拆包、粘包并限制缓冲长度；不能把一次串口读取当作一整帧。接收间隔可用于估计更新周期，但受缓冲影响，不等于曝光间隔。

视觉端使用 `uart.UART` 和 `write_str()`。保留写入长度检查是为了发现本地发送失败，不是增加通信校验。失败会报错退出；对端断线不一定使写操作失败，下位机必须检测接收超时。

### 下位机的阶段管理约定

1. 泊车期间继续接收、更新最新累计值，但不根据它触发巡线事件。
2. 启动或恢复巡线时，丢弃过期接收内容，以新的完整数据记录 `base_count`。
3. 本阶段计数为 `count - base_count`，不要按每条报文累加，也不要简单判断全程 `count == 3`。
4. 例如恢复时基准为 7，后来收到 10，本阶段新增 3 次确认；同一个 10 重复收到不会新增事件。
5. 若 `count` 下降，按视觉进程重启处理并重新同步。当前协议没有会话编号，不能保证识别所有重启情形。

恢复位置应避开旧交点，或确保旧交点的确认过程已经结束。如果恢复时旧交点只确认了 2 帧，下一帧才达到 3 帧，它仍会被算进新阶段；记录基准本身不能排除这种情况。

## 5. 用 MaixCAM2 测定参数

所有默认值都是起始值，不是通用标定结果。建议顺序：固定安装与光照 → 主 ROI → 灰度阈值与形态学 → 横线 ROI → 巡线零点 → 竖线与交点筛选 → 帧数与速度联合验证。每次只改变一组相关参数。

### 5.1 建立可重复的实测场景

准备正常车位姿、左右偏移、车头左右偏转、不同距离的交点、邻库有车/无车和反光场景。相机在车上实际位置采集，不能用手持画面代替安装后的标定。

记录曝光、增益等可用设置；若保留自动曝光，等待画面稳定并覆盖亮暗变化。设置方法以当前 MaixCAM2 固件支持的相机 API 为准，不直接套用其他板卡参数。

保留一份正常运行脚本，临时调试代码只加到调试副本中，测量后移除。屏幕缩放后的坐标必须换算回原始 `320 × 240` 图像坐标。

### 5.2 测量主 ROI 和横线 ROI

在多个实拍姿态中，确定能包含目标又避开车身杂物的矩形边界 L、T、R、B，按下面公式换算：

```text
MAIN_ROI_X_RATIO = L / FRAME_WIDTH
MAIN_ROI_Y_RATIO = T / FRAME_HEIGHT
MAIN_ROI_W_RATIO = (R-L) / FRAME_WIDTH
MAIN_ROI_H_RATIO = (B-T) / FRAME_HEIGHT
```

要求宽高为正，`X_RATIO + W_RATIO ≤ 1`、`Y_RATIO + H_RATIO ≤ 1`。当前四个比例为 `0.05, 0.00, 0.90, 0.55`，得到 `[16, 0, 288, 132]`。

再测量横线活动带的顶部 Y1、底部 Y2，注意比例基准是主 ROI：

```text
HORIZONTAL_ROI_Y_RATIO = (Y1 - main_roi[1]) / main_roi[3]
HORIZONTAL_ROI_H_RATIO = (Y2 - Y1) / main_roi[3]
```

当前 `0.48, 0.35` 得到 `[16, 63, 288, 46]`。横线在正常偏移和偏转时应仍有足够长度留在该带内，但带子不宜宽到引入大量库边线。改变主 ROI 后重新检查两个子区域。

### 5.3 测量二值化阈值和形态学核

当前 `BINARY_THRESHOLD=85`、`BLUR_KERNEL_SIZE=5`、`MORPH_KERNEL_SIZE=3`。二值化使用反相模式：预处理灰度值不大于阈值的像素变白，目标应表现为白线、背景为黑色。

在调试副本末尾，把原来的 `disp.show(img)` 暂时替换成以下一种，不能同时不断切换三种视图：

```python
disp.show(image.cv2image(gray, bgr=False, copy=True))  # 滤波后灰度，测阈值。
```

```python
disp.show(binary_img)  # 主 ROI 内二值结果，检查断线、噪点与粘连。
```

```python
disp.show(vertical_binary_img)  # 检查横线是否被剔除，竖线是否保留。
```

在灰度预览中分别框选黑胶带、普通白纸、阴影白纸与反光胶带，观察灰度分布。MaixVision 的框选直方图操作见 [官方预览与直方图说明](https://wiki.sipeed.com/maixpy/doc/zh/basic/maixvision.html)。

选择能覆盖大部分胶带、又低于大部分背景灰度的阈值。若没有可分离区间，先改善照明、反光或曝光；仅提高阈值会把阴影一并变白。先粗调再细调，记录多个场景，不用单个像素决定阈值。

高斯核使用正奇数；比较例如 3 与 5 时细线是否保留。形态学核过大会消除远处细线或把相邻目标连起来；在二值图上检查闭运算补缝、开运算去噪后的最终结果。`BINARY_WHITE_THRESHOLDS=[[200,255]]` 用来找二值图中的白色，不是原始黑胶带阈值，一般无需随光照调整。

### 5.4 测量巡线零点与横线筛选门限

把车放在希望保持的道路相对位置、车头平行于行驶方向，固定相机后采集多帧。在调试副本中、计算完误差后临时查看：

```python
if line_pixel_valid:
    print("line_y/pos/head:", line_y_at_trigger, position_error_px, heading_error_px)
```

取有效 `line_y_at_trigger` 的稳定均值或中位数作为 `TARGET_LINE_Y`，不要把无效帧计入。当前值为 `82.0`。改变 `MARK_TRIGGER_X_RATIO` 后，斜线的取样位置会改变，需重新测定零点。

`HEADING_SAMPLE_HALF_WIDTH=60` 当前对应 x=148 和 x=268，方向误差为 `y(268)-y(148)`。采样跨度过大可能依赖较远外推，过小则方向误差幅度较小；更改后必须重新调整下位机控制增益。理想车位姿下 `head` 应接近 0；若长期明显非零，先检查安装与选线，当前代码没有方向零点偏置参数。

在 `for candidate in lines:` 内、过滤之前临时记录端点、水平跨度、斜率，包含被过滤的真实线；只记录选中的线会漏掉失败样本：

```python
print("line:", candidate.x1(), candidate.y1(), candidate.x2(), candidate.y2(),
      abs(line_dx), line_dy / line_dx if line_dx else None)
```

| 参数 / 当前值 | 测定依据 |
| --- | --- |
| `LINE_MIN_LENGTH=60` | 真实横线最小水平跨度留余量；此处不是几何线段长度 |
| `MAX_HORIZONTAL_SLOPE=0.45` | 允许车姿下真实线最大绝对斜率留余量，同时排除竖线 |
| `LINE_MIN_AREA=100` | 库函数面积门限；通过真实线与噪声样本逐步调节 |
| `LINE_MIN_PIXELS=80` | 库函数有效像素门限；过高会漏掉较细或断裂的线 |

面积门限的精确定义请查阅目标固件对应官方文档，不把它等同于长度。下位机分别观察平移和转动车辆时 `pos/head` 的符号，再确定控制方向；它们均是图像量，不是厘米或舵机角度。

### 5.5 测量触发位置和竖线形状

在希望报告地标的位置摆好车辆，测量库边竖线中心 x：`MARK_TRIGGER_X_RATIO=x/FRAME_WIDTH`。当前为 `0.65`，触发中心 x=208。

`MARK_TRIGGER_HALF_WIDTH=34` 允许色块中心位于 x=174～242。窗口应让目标在最大车速下仍有足够帧完成确认，同时尽量避免两个地标同时进入。当前事件发生在窗口内连续确认后，不保证发生在 x=208；需要实测触发时刻的分散程度。

在 `for blob in blobs:` 内、形状过滤之前临时查看：

```python
print("blob x/y/w/h/cx:", blob.x(), blob.y(), blob.w(), blob.h(), blob.cx())
```

测量的是裁剪后色块的外接框，而不是原始画面中完整胶带。记录远近、偏转和反光下真实目标与干扰物的范围。

| 参数 / 当前值 | 测定依据 |
| --- | --- |
| `MARK_MIN_HEIGHT=14` | 低于真实目标最小可见高度，排除矮小噪点 |
| `MARK_MAX_WIDTH=28` | 高于真实目标最大宽度，同时排除宽块干扰 |
| `MARK_MIN_ASPECT_RATIO=1.8` | 真实目标最小 `h/w` 留余量，排除方块 |
| `MARK_MIN_AREA=50` | 配合真实样本逐步过滤小区域 |
| `MARK_MIN_PIXELS=35` | 配合真实样本过滤像素过少的色块 |

如果库函数已经把真实目标过滤掉，循环内不会有它的日志；在调试副本中暂时放宽面积/像素门限，再观察，并记录最终采用值。多个门限需要同时满足，例如 w=28 时，`h/w≥1.8` 要求整数高度至少 51。

### 5.6 测量倾斜裁剪间隔与交点距离

`VERTICAL_TO_LINE_GAP=3` 表示每列从 `int(y_line(x))-3` 开始向下清零。用 `vertical_binary_img` 检查左倾、右倾及较粗横线：横线残留会把多个竖线连在一起；间隔过大会截短竖线。

逐渐增大间隔，直到测试场景中的横线被分开且竖线保留足够高度。间隔应结合胶带在图像中的厚度和拟合误差确定，不能仅因为默认是 3 就固定不变。

`MIN_VERTICAL_ROI_HEIGHT=24` 是外包矩形的最小高度；它不会恢复逐列屏蔽掉的像素。应保持正数且不超过主 ROI 高度，不能用增大它来修复已被裁掉的竖线。

在候选循环计算出 `candidate_junction_y` 后、距离过滤之前临时记录：

```python
print("junction_gap:", abs(blob.y() + blob.h() - candidate_junction_y))
```

`MAX_JUNCTION_GAP=12` 应覆盖真实交点在裁剪、斜率和拟合误差影响下的距离变化，又尽量排除未连接竖线。这里是色块外接框底部到中心 x 处横线的纵向差，不是点到直线的垂直距离。调整裁剪间隔后必须重新测量此门限。

### 5.7 测量确认帧数、解除帧数和运行速度

当前 `JUNCTION_CONFIRM_FRAMES=3`、`JUNCTION_RELEASE_FRAMES=5`。在最快计划车速下，逐帧记录目标在窗口内连续合格的帧数，以及相邻地标之间窗口完全无合格形状竖线且横线有效的连续帧数。

确认帧数必须不超过目标连续合格帧数；解除帧数必须不超过相邻地标的有效空白帧数，同时应大于希望容忍的短暂漏检帧数。如果这些区间冲突，仅调参数不能可靠解决，需要缩小窗口、降低速度或改进跟踪逻辑。

可在状态更新后临时输出 `junction_streak, junction_clear_streak, junction_count`，但大量打印会降低帧率。正式性能测试应去掉打印，保留正式显示与 UART。

若需测量循环时间，在调试副本导入 `from maix import time`，循环开头记录 `loop_start_ms = time.ticks_ms()`，在 `disp.show(...)` 后记录本次耗时。`ticks_ms()` 用于读取启动后的毫秒时间，见 [MaixPy time API](https://wiki.sipeed.com/maixpy/api/maix/time.html)。周期受采集、识别、显示和发送共同影响，不能把摄像头标称 FPS 当作结果更新频率。

## 6. 更改分辨率时要重测什么

ROI 比例可保持相对位置，但相机视场或裁剪方式变化时仍需重测。若宽高都恰好扩大 k 倍且视场不变，可用以下关系作为重新标定的起点：

- 坐标、宽高、长度、间隔、采样距离约扩大 k 倍。
- 面积、像素数量门限约扩大 k² 倍。
- 斜率、高宽比通常无需按倍数改变。
- 灰度阈值、滤波核与形态学核根据新图像重新验证。
- 确认/解除帧数结合新处理帧率重新测量，不能按分辨率直接倍增。

## 7. 板端验收与记录

| 场景 | 观察项目 | 期望结果 |
| --- | --- | --- |
| 正常位置静止 | pos、head、valid | 误差稳定、valid=1 |
| 左右偏移与车头偏转 | 误差符号和幅度 | 连续可解释，不突然换线 |
| 遮住横线 | 串口 valid | 输出 0，累计值保留 |
| 单个交点停留 | count | 确认后增加一次，停留不连续增加 |
| 左倾、右倾横线 | 裁剪图、交点 | 横线被分离，真实竖线仍可识别 |
| 近处干扰 + 较远真实交点 | 选中红框 | 合格交点不被较近无效候选挡住 |
| 连续多个地标 | 实际地标数与 count 差 | 无漏计、重计 |
| 反光、遮挡、邻库有车/无车 | 丢线率、计数错误 | 满足实车允许误差，否则继续调试 |
| 泊车、出库后恢复巡线 | 基准和阶段差值 | 旧地标不污染新阶段 |
| 串口拔除、视觉重启 | 下位机超时和重新同步 | 不继续使用过期误差 |

建议将每轮标定记录为：日期、代码版本、固件/MaixPy、相机安装、光照、参数组、速度、有效帧率、已知地标数、实际增量、漏计/重计次数及现象。验收次数和误差限由比赛需求确定，未测项目不要填写“通过”。

## 8. 已知边界与排查

- **遮挡重计**：横线有效、竖线漏检达到解除帧数后，同一地标再出现可能被重新计数。
- **连续地标漏计**：两地标之间窗口未清空足够帧，锁定不会解除；无效交点形状的竖线也可能占住窗口。
- **跨帧身份未跟踪**：连续确认只判断每帧有候选，不保证三帧一定是同一个色块。
- **恢复基准边界**：旧地标尚未确认完时记录基准，随后可能污染新阶段。四字段数据未暴露该中间状态。
- **横线目标身份**：最长合格线不一定是需要跟随的道路横线；ROI 内出现其他相似线时需检查。
- **无像素到物理距离标定**：pos/head 不能直接解释为厘米、横向车距或转向角度。

这些边界不能用“语法通过”或“简单串口正常”消除。若实车场景触发这些问题，应记录原始画面和计数过程，再针对问题改进；不要只不断降低门限。

| 现象 | 优先检查 |
| --- | --- |
| 无画面或运行退出 | 板端日志、相机占用、固件模块、UART 引脚配置是否成功 |
| 经常 line:lost | 横线是否在蓝框内、二值图是否断线、跨度/斜率门限 |
| 看到竖线却不计数 | 裁剪图、宽高比、触发窗口、交点间隔、连续确认帧数 |
| count 停止增长 | lock 是否一直为 1，窗口内是否有残留或其他竖线 |
| count 偶尔多一次 | 遮挡解除锁定、反光断裂、同一地标重新进入 |
| 屏幕正常但下位机无数据 | A21→RX、共地、电平、115200/8N1、按换行解析 |
